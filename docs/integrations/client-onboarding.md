# Client onboarding

Internal activation checklist for each production client.

## 1. Create the client portal

- Create the customer from the internal admin dashboard.
- Use a real client email and a temporary password generated by the form.
- Confirm the response includes one organization, one property, three initial spaces and four initial devices.
- Share access only through the secure internal handoff process.

## 2. Review the first portal view

- Sign in as the client or use a controlled verification account.
- Confirm the portal shows the main site, watched spaces, cameras, sensors and alert counters.
- Confirm placeholder devices are clearly shown as pending connection and do not mention underlying providers.
- Confirm the client cannot access another organization's data.

## 2.4 Check database health

Before creating or connecting a real client, confirm the configured Supabase project has the expected schema:

```powershell
pnpm db:health
```

This does not create data. It checks the tables, columns and private evidence bucket needed by the portal, admin panel, gateway and camera flows.

## 2.5 Run the operational smoke test

Before using a real client account, run the reversible smoke test against the intended Supabase project:

```powershell
pnpm smoke:operational
```

The script creates a temporary client, gateway, critical event, incident action and camera signaling session, verifies the counts, then deletes the temporary organization and user. Do not proceed with a pilot if this command fails.

## 3. Activate the local connector

- Create one connector credential for the property.
- Install the connector in the protected site.
- Confirm the first heartbeat reaches SegurIA.
- Confirm inventory sync replaces or complements the placeholder devices.

## 4. Validate operational data

- Confirm cameras can provide a secure snapshot.
- Confirm a camera view request creates a short-lived session.
- Confirm events enter the activity feed.
- Confirm incidents, alerts and notifications keep the correct site context.

## 5. Close onboarding

- Mark placeholders that were replaced by real inventory.
- Add internal notes for exceptions and unsupported devices.
- Store any required connection credentials in the encrypted internal vault.
- Leave a gateway, inventory and audit trail for support.

## Done state

- The client can log in.
- The portal has useful data before and after the first connector sync.
- The admin team can see the company, site, connector, devices, events and audit trail.
- The client experience only speaks SegurIA.
