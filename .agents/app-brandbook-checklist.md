# `/app` Brandbook Checklist

Use this checklist before merging any change to the client portal.

## Visual

- [ ] Dark navy base is preserved.
- [ ] SegurIA blue is the only strong accent.
- [ ] Cards use soft radius and thin borders.
- [ ] The page has clear hierarchy in the first viewport.
- [ ] No section looks like a generic SaaS dashboard.
- [ ] Spacing feels intentional and premium.

## Copy

- [ ] Headlines are short and clear.
- [ ] The client can understand the page in 5 seconds.
- [ ] The wording avoids technical jargon.
- [ ] Alerts and actions are described in plain Spanish.
- [ ] Empty states are readable and calm.

## Structure

- [ ] There is one primary action.
- [ ] Risk or status is visible near the top.
- [ ] Cameras, alerts, and sites are easy to find.
- [ ] The page does not overload the user with metrics.
- [ ] The layout remains understandable on desktop and mobile.

## Brand compliance

- [ ] Tone feels calm, premium, and operational.
- [ ] The page matches the rest of SegurIA.
- [ ] The page does not introduce off-brand colors or fonts.
- [ ] Visual effects stay subtle and functional.
- [ ] The user can tell this is SegurIA without reading a lot.

## Final review output

When reviewing `/app`, record:

- Compliance status: pass / partial / fail
- Brand issues: list the visible problems
- Priority fixes: list the first changes to make
- File scope: exact files touched
